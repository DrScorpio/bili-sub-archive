## 1. 项目概述

bili-sub-archive（命令 `bsa`）是 Windows 上**手动运行的 Python 命令行工具**。
输入一个 B 站 UP 主 UID 与自己的 Cookie，把该账号**当前可见**的动态、视频、专栏按条目归档到本地：

- 动态 → `content.md` + 原图 + **单张长 PNG**；
- 专栏 → `article.md` + 原图；
- 视频 → 分 P 媒体 + 文字稿（平台字幕优先、本地 ASR 兜底）+ 逐视频总结 + Mermaid 思维导图。

**定位**：个人本地使用。不提供公开分享、付费内容破解或登录权限绕过；充电内容只在
Cookie 对应账号本身有权限、且平台实际提供时处理，无权限的条目如实记录原因。
**不提供定时任务、GUI、互动视频与直播回放处理。**

## 2. 需求范围与边界

| 维度 | 要求 |
| --- | --- |
| 输入 | UID 必填（启动时校验格式并取作者名与头像）；Cookie 由环境变量或未入库的本地配置提供 |
| 范围 | 动态/视频/专栏可分别开关；支持首次采集与增量重跑 |
| 筛选 | 日期起止（北京时间闭区间）；或三类**合计**取最新 N 条；两者同时给出时先筛日期再取最新 N |
| 文字 | 平台字幕优先；无字幕时可选本地 ASR（**默认关闭**）；**不提供本地视频画面 OCR**（见 3.5） |
| 总结 | OpenAI 兼容接口；端点/模型/密钥/自定义 prompt 均由用户配置；只发送文字稿 |
| 导图 | `mindmap.mmd`（可编辑源文件，确定性序列化）+ `mindmap.png`（mermaid-cli 渲染） |
| 运行 | Windows + Python 3.11+；手动运行；单条失败不中断整批 |

**已确认边界（原始需求第 7 节）**：不纳入互动视频与直播回放；不做定时任务；
动态只出单张 PNG（高度随内容增长，不分页）；视频文字来源只有"平台字幕 + 本地 ASR"两种；
不承诺"指定 UID 下所有充电内容必然完整列出"。

**验收标准（原始需求第 6 节，共 7 条）**：三类内容可归档且重跑不重复；多图动态有完整长图；
有字幕的视频有带时间戳文字稿 + 总结 + 导图源文件与 PNG，无字幕按开关处理且失败有明确状态；
下载并发可配、失败后只补未完成步骤；凭据/权限/模型失败要报具体原因且不泄露凭据；
日期范围与最新 N 两种模式都能跑、多 P 归一个文件夹；ASR 开关生效且关闭时不跑识别。

## 3. 技术方案

### 3.1 模块与数据流

```text
CLI / 配置校验
  -> 登录态检查
  -> 采集适配层：三类分页发现
  -> 时间范围过滤 + 全局发布时间排序 + 合计最新 N 条
  -> 按 (类型, 平台 ID) 建立/查找条目目录与状态
  -> 动态: 正文/原图 -> 单张 PNG
  -> 专栏: 正文/内嵌图片 -> Markdown
  -> 视频: 各 P 下载 -> 字幕/本地 ASR -> 合并文字稿
            -> LLM 分段总结 -> 合并总结 -> 大纲 -> .mmd -> PNG
  -> 更新 index.json -> 输出运行摘要
```

代码结构（当前）：

```text

  config.py        TOML + 环境变量 + 命令行三层合并与校验
  credentials.py   Cookie / UID / LLM 密钥来源与优先级
```

### 3.2 平台接口白名单与适配层契约

**核心决策：自研薄适配层（标准库 `urllib` + WBI 签名），不引入第三方 B 站封装库。**
业务代码不得直接拼 URL，只能调用白名单接口。

| 域 | 接口（去重后共 **16 个**） | WBI | 用途 |
| --- | --- | --- | --- |
| 基础 | `nav` | 免 | 登录态判据（`code==0 && data.isLogin`） |
| 基础 | `finger/spi` | 免 | 设备 buvid |
| 基础 | `card?mid=` | 免 | 作者名/头像（替代匿名声明的 `space/wbi/acc/info`） |
| 视频 | `space/wbi/arc/search` | 需 | 投稿列表（公开 + 充电子集视图） |
| 视频 | `x/web-interface/view` | 免 | 视频详情 |
| 视频 | `x/player/pagelist` | 免 | 分 P 清单 |
| 视频 | `x/player/playurl` | 免 | 播放地址与权限判定 |
| 动态 | `feed/space` | 需 | 主动态列表 |
| 动态 | `opus/feed/space` | 需 | 图文动态（次级来源） |
| 动态 | `v1/detail` | 需 | 动态详情（`modules` 是 **dict**） |
| 动态/专栏 | `opus/detail` | 需 | 图文详情（`modules` 是 **list**，参数名是 `id`） |
| 专栏 | `opus/feed?type=article` | 需 | 新格式（opus）专栏列表 |
| 专栏 | `x/space/wbi/article` | 需 | 旧格式（read/cv）专栏列表 |
| 专栏 | `x/article/view` | 免 | 旧格式专栏详情（HTML） |
| 字幕 | `x/player/wbi/v2` | 需 | 字幕清单 |
| 字幕 | 平台返回的 `subtitle_url` | 免 | 字幕本体（CDN，临时签名地址） |

**契约要点**（原始清单共 11 条，此处为汇总）：

1. 适配层对三类条目统一输出 `kind / id / published_at / url / title / author / raw_ref`；
   时间内部带时区，目录日期按北京时间换算。
2. 默认带登录 Cookie，**不提供匿名产品路径**——匿名访问空间类接口会出现 `-352` / HTTP 412
   或偶发成功，不稳定。
3. **不把 `code=0` 当作"可读"**：充电视频无权限时接口同样返回 `code=0`，必须看媒体流形态
   （见 3.3 权限判定）。
4. 分页终止一律用 `has_more` / 实际条目数，**不用 `count`**（`count` 仅作交叉校验并写进扫描统计）。
5. 请求间隔 + 抖动，`opus/detail` 串行；遇风控退避，**不做验证码绕过或账号轮换**。
6. `-352` / HTTP 412 是间歇性风控：逐条记状态、可重跑补做，**不写成终态失败**。
7. `62002` 同时覆盖"已删除"与"无权限"，不可区分 → 状态如实写"稿件不可见（62002）"。
8. 未登录时字幕清单接口返回**空数组而非错误**（静默失败）；未登录不得判为"无字幕"。
9. 充电动态未授权时 `opus_id` 与授权一致，但正文被截断、`modules` 为 `MODULE_TYPE_BLOCKED`
   → 必须标权限不足，不得把截断正文当完整归档。
10. 临时签名地址（如字幕 CDN 链接）只驻内存，不写进 `metadata.json`，重做时重新取。
11. 产物出现凭据值即以退出码 3 终止。

### 3.3 关键设计决策

| 主题 | 决策 | 依据 / 后果 |
| --- | --- | --- |
| 限速 | 默认请求间隔 **1.2s**（另加抖动）；`opus/detail` 串行 | 实测 0.9~1.2s 较稳；小于 0.5s 告警 |
| 风控 | `-352` / HTTP 412 → 清空 WBI 密钥 + 指数退避；连续 3 次停止本次运行 | 不绕过验证；退出码 5 提示人工处理 |
| 权限判定 | 取 `playurl` 后按 `dash.video` 路数 / `durl` 段数判 `full / preview_only / unknown` | 只看 `code` 会把试看当正片；`preview_only` 的媒体记 `skipped`，**绝不下试看** |
| 条目身份 | `(类型, 平台 ID)`；目录 `YYYY-MM-DD_<类型>_<标题摘要>_<平台ID>` | 标题变化不重命名目录；作者目录按 UID 定位，改名不新建第二个目录 |
| 状态机 | `pending / running / done / skipped / failed`，`skipped` 必带 `reason` | 是 `retry` 与"失败可重试"清单的机读依据；门控类跳过同时写 `errors[]`，避免反复打接口 |
| 落盘 | 临时文件 + 原子替换；产物可读且校验通过才标 `done` | 中断恢复、判重、避免半截文件 |
| 写锁 | 同一作者目录单写者；`.lock` 陈旧判据 **6 小时**可抢占并告警 | 上次被强杀后不必手工删锁 |
| 增量 | 重跑按平台 ID 判重、只补未完成步骤；改 prompt/模型只重做总结与导图 | 不重复下载、不重复调用模型 |
| 接管机制 | `stale_skip_map`：按**步骤**维护"哪些跳过原因现在应重做" | 阶段推进（`IMPLEMENTED_STAGE`）与配置变化（`*_disabled`）都靠它；`permission_preview_only`、`content_blocked`、`no_media`、`no_speech`、`no_images` 是终态，明确排除 |
| 输入指纹 | 总结指纹 = prompt + 模型 + 端点 + 客户端 + 分块参数 + 文字稿（字数 + 散列前缀）；导图指纹 = 总结指纹 + 节点/深度/标签/宽度/背景 | 指纹一致且产物齐全则复用、不调模型；`--force` 强制重做 |
| 分块不丢尾段 | `max_chunks` 是**成本上限**而非内容上限；超限时放大每块字数，按空行边界切、保留尾部重叠 | `chunk.uncovered_ranges()` 恒空是"不丢尾段"的机器可验证形式 |
| 大纲与导图 | 模型只产**受控缩进大纲**，不直出 Mermaid；`max_depth` 过深节点**压平**而非丢弃，`max_nodes` 硬截断 | `.mmd` 同树恒等（确定性），12 类 Mermaid 语法字符统一转全角；PNG 失败保留 `.mmd` 可重试 |
| 文字稿时间基准 | 保留各 P 原始时间戳，P 号写进 cue 前缀 `[P01]`，P 边界插入说明 cue，`time_base="per_page"` | 需求不强制拼接媒体；时间戳可直接对 `videos/P01.mp4` 定位 |
| 缺失依赖 | 缺 Pillow / yt-dlp / mmdc / ffmpeg 时记 `failed(dependency_missing)` 或降级，并给安装命令 | 每次 `sync` 重试一次——这是"可补做"的正确语义，不是静默失败 |
| 降级诚实性 | `ffprobe` 不可用时降级为"大小阈值 + 容器魔数"，`verify_note` 明写"可播放性未经解码验证"；无 ffmpeg 时禁用 DASH 分离流并把"清晰度可能更低"写进摘要 | 不冒充"已验证"；不静默降级 |
| 长图超限 | 超过 `[render] max_height` 时 `clamped=True` 且明确告警"正文可能不完整" | 明确告警，不静默截断 |
| 终端输出 | 交互终端彩色 + 实时进度，重定向自动退化纯文本；`rich` 可选，缺失用内置纯文本皮肤 | 版式、信息量与退出码完全一致；`--json` 永远是纯 JSON |

### 3.5 不提供本地视频画面 OCR 的决策

**2026-09-23 决定：视频文字来源只有"平台现成字幕"和"本地 ASR 语音转写"两种，不产生 `ocr.txt`，不引入 OCR 依赖链。**

依据：

1. **收益低**：抽样公开视频前 10 条 **10/10** 都带 AI 中文字幕，画面 OCR 属于第三层冗余。
2. **代价高**：候选 OCR 栈（paddle 系）在当时的 Python 版本上**没有任何可用 wheel**，
   且其上层封装钉死了另一个无对应 wheel 的依赖，无法源码回退；OCR 还需 ffmpeg 抽帧 +
   本地推理 + 采样去重，是安装复杂度与资源消耗的主要来源。
3. **可回退**：随时可另评估 ONNXRuntime 系方案再加回。

副作用：当时无已知依赖阻塞，可以继续使用较新的 Python 版本。

### 4.1 阶段 0：平台与组件验证

**方法**：三身份矩阵（登录态 / 仅设备标识 / 匿名）交叉探测；登录账号非大会员；
样本覆盖公开与充电的视频、动态、专栏。产物一旦出现凭据值即退出码 3。

**平台结论（当时实测）**：

| 主题 | 结论 |
| --- | --- |
| 三类可发现性 | 视频公开列表 `count=211`、充电子集 `count=88`；动态列表每页 11~13 条，图文动态每页 20 条；专栏样本账号 44 篇 |
| WBI 是否必需 | `space/wbi/arc/search`、动态全部接口、专栏新格式列表/详情、字幕清单需要；`nav`、`finger/spi`、`card`、`view`、`pagelist`、`playurl`、`article/view`、字幕本体不需要 |
| 取密钥 ≠ 已登录 | 匿名也能拿到 WBI 密钥；判据必须是 `code==0 && data.isLogin` |
| Cookie 失效 | 与未登录同为 `-101`，不可区分 → 提示语合并为"登录态无效或已过期" |
| 充电可见性 | 充电专属视频在**公开投稿列表里直接可见**（自带充电标记），无需已知链接；充电列表只是另一翻页窗口，两列表首屏有交集 |
| 充电权限 | 授权得到 12 路 DASH 视频流；未授权同样是 `code=0`，但 DASH 0 路 + 单段 `durl`（试看）→ 判定依据是媒体流形态 |
| 字幕 | 授权样本 2~6 条（多语种）；匿名 0 条；字幕本体在 CDN 匿名可下载，样本 **900 段**，`from/to` 为秒 |
| 错误码 | `-101` 未登录、`-400` 参数错、`-404` 不存在、`-352` WBI 风控、HTTP 412 风控（无 JSON body）、`62002` 稿件不可见（已删除/无权限**不可区分**） |
| 风控特性 | `-352` 为间歇性：同一样例连续三次"成功→风控→成功"；放慢间隔 + 失败后隔 2s 重试可全量通过 → 必须可重跑补做 |
| 解析坑 | `major.opus.summary` 是富文本对象而非字符串；`v1/detail` 的 `modules` 是 dict，`opus/detail` 是 list；`opus/detail` 参数名是 `id`；列表不提供发布时间须走详情 |
| 专栏两种格式并存 | 新格式（`type=1`，正文在 `paragraphs[]`）与旧格式（`articles[]` + `article/view?id=<cv>`）需**双查去重**；样本账号 44/44 全是新格式，旧格式只有离线证据 |
| 媒体下载 | 动态原图与专栏图可匿名下载；图片地址返回 `http://` 需升级 `https`；图片 CDN 不校验 Cookie，下载失败不应归因权限 |
| 分页 | 不以 `count` 判断终止，一律用 `has_more` |

**组件结论**：见 3.4。另外当时确认了一个易错点——**没有某平台的 wheel tag ≠ 不可用**：
走 `abi3` 的依赖（如 `tokenizers`、`pycryptodomex`）没有对应版本 tag 也能安装。

### 4.2 阶段 1：基础归档

**交付**：CLI（`check` / `sync` / `retry`）、四层配置（默认值 < `config.toml` < `config.local.toml` < 环境变量/命令行）、
脱敏、错误分类、原子写入与单写者锁、`index.json` + `metadata.json` 状态机、时间筛选与跨类最新 N、
分页发现与去重、动态与专栏归档。

**要点**

- 图文动态配图布局顺序：主动态段落 → 主动态卡片 → 转发原文段落 → 转发原文卡片；
  未被正文消费的图片落入 `## 配图` 节（首轮出现过"图下载了但正文没引用"，已修复并加测试锁死）。
- 门控内容的正确表达是 `content=skipped(content_blocked)` + `errors[]`，而不是把抓取记成失败。
- 风控计数不能与内部设备标识请求耦合（清空 WBI 后重取必然成功，会错误清零计数）。
- 测试沙箱拒绝随机短名临时目录 → 离线测试统一用 `.test_tmp/case_*`。

**验证**：离线 **155** 例全过（约 15s；测试内关闭刷盘以避开 Windows 每次落盘开销）。
联网冒烟 7 次运行 **0 风控 0 重试**：`--latest 6` 归档 6 条动态；幂等重跑全部 `skipped` 且目录集合不变；
`--types article --latest 2` 归档 2 篇专栏；日期范围筛选把 50 个候选收敛到 4 条；
`retry` 报告"没有需要补做的条目"；`check --scan-output` 未发现凭据值；视频条目仅取元数据。
门槛：**10 条目 / 6.27 MiB**，图片不变量 **11 下载 = 11 引用 / 0 违例**（固化为断言）。

**遗留**：样本账号 44 篇专栏**全是新格式**，旧格式 `read/cv` 分支只有离线样本证据；
`62002` 不可区分"已删除/无权限"；充电视频无权限时只有试看；部分配图失败记 `partial`；
发现阶段取不到发布时间的条目不进最新 N 候选（不猜时间）。

### 4.3 阶段 2：媒体与本地文字

**交付**：可选依赖探测、yt-dlp 媒体下载、字幕提取、本地 ASR 兜底、跨 P 文字稿合并、
动态长图渲染、单条检查工具。

**要点**

- **接管机制**是本阶段最关键的设计：阶段 1 把媒体/文字稿/渲染记成"未实现就跳过"且已结算，
  而状态机把 `skipped` 当终态，于是新阶段落地后 `retry` 永远不会碰这些条目。
  解法是按**步骤**维护"哪些跳过原因现在应重做"（阶段推进 + 本次开关变化），
  并明确排除终态原因（如 `permission_preview_only`、`content_blocked`）。
  按原因一句话匹配是不够的：`no_transcript` 对文字稿步骤是终态，对总结/导图步骤却是"等下一阶段"。
- 媒体字节单独累加（yt-dlp 不走内建 HTTP 客户端），否则运行摘要的下载量会漏。
- 权限判定优先于下载开关：`--no-media` 时无权限仍记 `denied`，不能变成"跳过"。
- "没有字幕"（`no_subtitle`，良性、可开 ASR 补做）与"取字幕失败"（`failed`，可 `retry`）必须分开；
  早期两者都被吞成 `skipped`，已修正。
- ASR 失败三分类：无媒体（终态）/ 无语音（终态）/ 转写失败（可重试）。
- 长图：中文逐字换行、高度随内容增长、配图"只缩不放"居中；缺 Pillow 返回依赖缺失而不抛异常
  （有单测扫描源码守住"模块顶层不 import Pillow"）。

**验证**：离线 **291** 例全过（约 33s，本阶段 +136），全部用替身，不联网、不跑模型。
门槛：2 P 视频两个媒体文件落盘且逐个校验；4 图动态长图 **1080×8601 / 2.2 MB**；
ASR 关闭时转写记 `skipped` 且转写器调用次数为 0；部分分 P 失败后重跑**只补失败分 P**；

**诚实说明**：视频媒体下载与本地 ASR 的**联网端到端未在开发机跑通**
（当时未安装 yt-dlp / FFmpeg / faster-whisper），覆盖来自离线替身 + 阶段 0 的媒体流形态实测
+ 组件官方文档参数。交付前需在装好 FFmpeg 的机器做一次授权在线验收。

### 4.4 阶段 3：总结与思维导图

**交付**：LLM 客户端（SDK / 标准库双路径）、分块、prompt、受控大纲、Mermaid 序列化与渲染、
以及一个本机替身模型服务与导图检查工具。

**要点**

- 触发词档位：`max_tokens` 默认 **8192**（代码内置默认 2048）。推理模型的思考 token 也计入上限，
  2048 常在写完正文前用光，表现为"模型返回内容为空"或摘要断在半句、大纲缺失。
- 自定义 prompt 同时支持真 TOML（`system` / `map` / `reduce` / `full` 四个顶层键）与 INI 分节写法；
  缺哪节用哪节的内置默认；`map`/`full` 必须含 `{transcript}`、`reduce` 必须含 `{points}`，
  缺失直接报配置错误，不会静默发出空内容。写完即算"prompt 变更"→ 自动重做总结与导图。
- **只发送文字稿**：不发送 Cookie、媒体文件或原视频地址；`metadata.json` 只记端点主机名；
  密钥只进请求头，落盘与日志统一过脱敏。
- 自检断言：请求体里登录凭据出现 **0 次**。
- 受控大纲：模型只产缩进大纲；过深节点压平（不丢节点）、节点数硬截断、标签截断、同层去重；
  无可用大纲时确定性派生并标注来源。
- 复用判据依赖 `metadata.extra.summary.signature`；阶段 1/2 的旧产物没有该字段 → 首次 `retry`
  视为需重做（预期行为）。

**验证**：离线 **393** 例全过（+102，约 44s）。本机没有可用的云端模型，改用**本机回环的
真实 HTTP + JSON 确定性替身**跑真实归档产物：一份约 10,013 字的合并文字稿 → 4 块
（每块 3000 字 + 200 字重叠）→ 5 次调用（4 次要点 + 1 次合并）；尾段最后 60 字出现在最终
`summary.md` 中；`.mmd` 结构检查通过；5 次请求的 JSONL 里凭据命中 0 次、鉴权头为空。
导图检查自动挑最长真实中文文字稿（约 32 KB）→ 派生大纲 → 9 节点 / 2 层；如实报告
渲染器缺失、PNG 未生成（退出码 1 = "渲染未完成"，不是链路失败）。

**未实测**（不要当成已验证）：真实第三方模型的兼容性/限流/长上下文；`mindmap.png` 的真实渲染；
`openai` SDK 路径只被替身模块覆盖；个别新模型只认 `max_completion_tokens`，用旧字段会 400；
分块按字数而非 token；大纲质量取决于模型；正文少于 `min_chars` 的 `insufficient_text` 是终态。

## 6. 已知限制

### 6.1 平台侧（实测结论）

1. 已删除与无权限同为 `62002`，接口层**不可区分** → 状态原样记"稿件不可见（62002）"。
2. 充电视频无权限时接口不报错，只给试看片段 → 记 `permission=preview_only`，
   媒体记 `skipped`，**绝不下试看当正片**。
3. 充电条目仅部分可从列表发现（公开列表与充电子集是不同翻页窗口）→ 如实标注额外扫描成本与差异，不承诺全量。
4. 未登录时字幕接口静默返回空数组 → 适配层在未登录时直接以登录态错误终止，不把"空"当"无字幕"。
5. 样本 UP 的专栏全部是新格式 → 旧格式分支只有离线证据（见未实测项 5）。
6. `max_pages` 默认 40，极端账号可能翻不完 → 扫描统计记 `stopped_by` 并在摘要告警。
7. 发现阶段取不到发布时间的条目不进最新 N 候选 → 摘要给出条数与"重跑可补做"，不猜时间。

### 6.2 工程限制

1. 分块按**字数**而非 token，与模型真实上下文有偏差；超预算时先"要点再压缩"再合并，并如实写说明。
2. `insufficient_text` 是终态：正文少于阈值不生成总结，补齐文字后用 `--force` 重做。
3. 无 ffmpeg 时只能下渐进式单流，清晰度可能低于预期，摘要会说明"装好 FFmpeg 后可 retry"。
4. `ffprobe` 不可用时降级为魔数校验，`verify_note` 如实写明，不冒充已验证。
5. 依赖缺失时媒体/渲染记 `failed`，每次 `sync` 重试一次——这是"可补做"的正确语义。
6. 动态长图超过高度上限会截断，但会明确告警，不静默处理。
7. 多 P 媒体不拼接为单文件；合并文字稿保留各 P 原始时间基准。
8. 无 CI：回归靠手动跑离线套件。

## 7. 隐私、凭据与合规

- Cookie、LLM 密钥、含充电内容的本地归档都视为敏感数据；**日志与异常输出统一过脱敏器**，
  产物里只允许出现凭据的**字段名**，绝不出现值。`check --scan-output` 会回扫产物，
  发现任何凭据值即以退出码 1 报错。
- 凭据来源优先级：环境变量 > `config.local.toml`（不入库）> 遗留明文凭据文件（已 gitignore，建议不再使用）。
- 归档默认只保存在本机；只有显式配置总结端点后，**文字稿**才会发给用户选定的服务，
  不发送 Cookie、媒体文件或原视频地址。
- 本地 ASR 全程离线；关闭时既不下载模型、也不跑识别，更不会把媒体发给云端识别服务。
- 平台请求有间隔与并发上限；遇风控/限流即退避，明确风控则停止并提示人工处理，
  **不做验证码绕过、权限破解或账号轮换**。

## 10. 术语与占位符

| 词 | 含义 |
| --- | --- |
| `UID` | 目标 UP 主的数字 ID；本文一律写作 `123456789` |
| `条目` | 一条动态/视频/专栏，身份是 `(类型, 平台 ID)` |
| `步骤` | 条目内的处理单元（fetch / media / transcript / render / summary / mindmap 等），各自有状态与 reason |
| `reason` | 跳过或失败的具体原因码，如 `no_transcript`、`llm_not_configured`、`dependency_missing`、`permission_preview_only` |
| `preview_only` | 账号对该充电内容只有试看权限；媒体不下载 |
| `WBI` | 平台对部分接口要求的请求签名 |
| `指纹` | 输入参数的散列，用于判断"已完成但已过时"，决定是否重做 |
| `evidence / problems / pending` | 验收工具的三类结论；只有 evidence 非空算 PASS |
