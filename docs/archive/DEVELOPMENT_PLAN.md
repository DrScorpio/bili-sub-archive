## 1. 交付目标

交付 Windows 上可手动运行的 Python 命令行工具。输入 UID、Cookie、日期范围或最新 N 条，归档当前账号可见的动态、视频、专栏；视频下载并生成文字稿、总结和 Mermaid 思维导图，动态生成单张长 PNG。最新 N 条在三类内容中按发布时间合计选取。ASR 仅在本机运行，用户控制开关；总结通过用户指定的 OpenAI 兼容接口完成。不提供本地 OCR。

不开发 GUI、定时任务、互动视频或直播回放处理，不尝试绕过充电权限或平台风控。实施时以需求文档为产品范围，平台能力不确定的部分先验证，不能以猜测承诺覆盖率。

## 2. 前置验证与技术选型

### 2.1 平台可行性验证（第一道关口）

用测试账号和有权访问的样本分别验证公开/充电的动态、视频、专栏：

1. UID 对应作者信息与三类列表是否可读取；充电条目能否从列表发现，还是只能通过已知链接访问。
2. 列表分页、发布时间、置顶项、转载/投稿动态与专栏正文的字段及排序是否稳定。
3. 同一 Cookie 能否读取已授权条目的详情、动态原图、专栏图片、视频分 P、播放地址与字幕。
4. 无权、已删除、Cookie 失效、请求被限流时是否可区分；记录实际响应与可用范围，不保留测试账号的凭据。
5. 验证候选封装库的维护状态和许可证，再决定是否在采集适配层使用；不把未验证接口散布到业务代码中。

**通过条件**：三类公开内容至少各有一条完成“列表 -> 详情 -> 本地文件”；充电内容按实际授权样本分别验证。若某类充电条目无法从列表发现，先如实报告可发现范围并与需求对齐，再进入大规模下载开发；不采用验证码绕过、伪造购买状态等方式补齐。

### 2.2 拟用组件

| 职责 | 拟用方案 | 采用前验证 |
| --- | --- | --- |
| B 站采集 | 独立 `BilibiliClient` 适配层（自研，标准库 `urllib`）；不引入第三方 B 站封装库 | 阶段 0 已验证：16 个接口打通、列表/详情/充电可见性、Cookie 传递、依赖许可证 |
| 视频下载 | `yt-dlp` Python API，`ffmpeg`/`ffprobe` 合流、提取音频和检查媒体 | 授权样本的清晰度、分 P、Cookie、续传及并发效果 |
| 字幕/本地 ASR | 字幕解析；无字幕且开关启用时使用 `faster-whisper` | Windows CPU 路径、中文样本、时间戳、模型首次下载 |
| 动态图片 | Pillow 排版文本、头像及配图 | 中文字体、长图宽高、多图和转发排版 |
| 总结 | `openai` Python SDK 的 Chat Completions，配置 `base_url`、模型与密钥 | 用户选定服务的实际兼容性和上下文长度 |
| 导图 | 先生成结构化大纲，再确定性转为 Mermaid mindmap `.mmd`；Mermaid CLI 渲染 PNG | 中文标签、特殊字符、长节点与本机渲染环境 |
| 本地状态 | 每条 `metadata.json` + 作者级 `index.json`，原子写入 | 中断恢复、判重、目录迁移及格式版本 |

Python 与第三方依赖固定兼容版本；Windows 安装指引覆盖 Python、FFmpeg、Node.js/Mermaid CLI，以及可选的本地 ASR 模型。ASR 依赖按功能分组安装，未启用时不要求下载模型。模型首次下载属于安装准备，识别过程不调用云端识别接口。

## 3. 模块与数据流

```text
CLI / 配置校验
  -> 登录态检查
  -> BilibiliClient 三类分页发现
  -> 时间范围过滤 + 全局发布时间排序 + 合计最新 N 条
  -> 按 (类型, 平台 ID) 建立/查找条目目录与状态
  -> 动态: 正文/原图 -> 单张 PNG
  -> 专栏: 正文/内嵌图片 -> Markdown
  -> 视频: 各 P 下载 -> 字幕/本地 ASR -> 合并文字稿
            -> LLM 分段总结 -> 合并总结 -> 大纲 -> .mmd -> PNG
  -> 更新 index.json -> 输出运行摘要
```

### 3.1 发现和筛选

- 适配层对三类条目统一输出 `kind`、`id`、`published_at`、`url`、`title`、`author`、`raw_ref`，时间在内部用带时区的值，目录日期按北京时间生成。
- 同时指定日期与最新 N 时，先筛日期，再在三类候选中按发布时间降序选 N 条；同秒以类型、平台 ID 固定顺序打破平局。置顶项仍按真实发布时间排序。
- 每类列表分别翻页，直到能够证明后续页不会进入结果集，或到达页尾。若某列表无法保证发布时间排序，不因已凑满 N 条就提前停止；将额外扫描成本和接口限制显式报告。
- 仅保存已实际发现的条目；“未发现”不写成“权限不足”。识别到但不可访问的条目保存状态与错误，不下载其内容。

### 3.2 文件与状态契约

- 作者目录：`<UID>_<清理后的UP名称>`；条目目录：`YYYY-MM-DD_<类型>_<清理后的标题或摘要>_<平台ID>`。同一 UID 的名称变化不应生成第二个作者目录，以 UID 为定位依据。
- 条目身份为 `(kind, platform_id)`，目录路径在首次创建后记录于 `index.json`，标题变化不触发目录重命名。路径组件截断并清理 Windows 保留字符与保留名称。
- `metadata.json` 包含原链接、作者、发布时间、分 P、处理步骤状态、错误码、更新时间、格式版本及模型/prompt 指纹；不包含 Cookie、API 密钥或临时下载 URL。
- 每步状态取 `pending/running/done/skipped/failed`；文件写入临时文件后原子替换，只有产物可读且校验通过才标记 `done`。重跑跳过有效产物，失败步骤及其下游依赖可重试；变更 prompt 或模型只重做总结/导图，开启 ASR 只补做文字及下游。
- `index.json` 是可重建的条目索引；条目 `metadata.json` 为步骤状态的依据。一次运行只允许一个进程写入同一 UID 的目录，避免并发修改索引。

### 3.3 各类产物

- **动态**：`content.md`、`images/` 原图、`render.png`。下载头像与原图供本地渲染；图片按原顺序排布，中文断行、表情替代文本、转发来源和长图布局用样本测试。可见但不可表达的卡片保留文字/链接及缺失说明；不采集评论。
- **专栏**：`article.md`、`images/`。正文结构解析为标题、段落、列表、图片；图片改写为相对路径，无法取得的图片保留原链接和错误状态，不以空白替代正文。
- **视频**：同一 BV 号一个文件夹，`videos/P01.*` 等分别保存各 P，不强行拼接媒体。各 P 保存带时间戳的字幕/ASR 片段及来源；合并 `transcript.txt` 和 `transcript_timed.srt` 时标记 P 号与时间基准。
- 缺少字幕且关闭 ASR 时不得把简介当作文字稿；文字不足则总结/导图标记 `skipped: no_transcript`。
- 总结将逐段文字按 P 和时间整合，超出模型上下文时分块总结再汇总；保存 `summary.md`、模型名、prompt 指纹和生成时间。LLM 输出先解析为受控层级大纲，转义 Mermaid 特殊字符后写 `mindmap.mmd`，渲染并检查 `mindmap.png`。PNG 失败保留 `.mmd` 供重试。

## 4. 命令行与配置设计

计划提供 `sync`、`retry`、`check` 三个子命令：

```powershell
subvideo check
subvideo sync --uid 123456 --from 2026-01-01 --to 2026-09-23
subvideo sync --uid 123456 --latest 20 --asr --video-workers 3
subvideo retry --uid 123456 --steps summary,mindmap
```

`sync` 支持指定内容类型、输出路径、ASR 模型及 prompt 文件；`retry` 只补做失败或被配置变更影响的步骤。配置使用本地 TOML；Cookie/API 密钥优先从环境变量读取，也允许由未入库的本地配置文件提供。模板配置只含占位符，日志和异常输出统一屏蔽敏感字段。未配置 LLM 时归档与转写照常完成，总结/导图标记待配置；`check` 检查依赖、配置和登录态，不发起批量下载。

默认开启媒体下载与现成字幕提取；ASR 默认关闭，避免未经用户选择就下载模型或执行高负载识别。视频下载有“同时处理的视频数”和“单视频分片并发数”两个上限，并设置全局请求速率；本地 ASR 串行或限制为低并发，避免与下载线程争用过多资源。具体默认数值经授权样本压测后固定。

## 5. 实施阶段与验收

| 阶段 | 工作与产物 | 完成门槛 |
| --- | --- | --- |
| 0. 平台验证 | 登录态、三类列表/详情、公开与授权充电样本验证记录；确认适配策略 | 明确每类可发现/可读取范围及无法覆盖的情况 |
| 1. 基础归档 | 项目结构、CLI/TOML、采集适配层、时间筛选、跨类最新 N、索引/状态、动态与专栏归档 | 三类公开样本可归档，重跑不重复；日期和合计 N 筛选正确 |
| 2. 媒体与本地文字 | 视频并发下载/续传、分 P、字幕、本地 ASR、动态单张长 PNG | 多 P 与多图样本产物完整；关闭识别不运行模型；失败后补做 |
| 3. 总结与导图 | OpenAI 兼容接口、自定义 prompt、长稿分块、`.mmd` 与 PNG | 每个有文字稿的视频一份总结和导图；模型失败可独立重试 |
| 4. 稳定与交付 | 单元/集成/授权样本测试、Windows 安装和使用说明、配置模板 | 需求文档第 6 节验收项逐条通过，已知平台限制列入交付说明 |

阶段 0 未过关时暂停依赖该能力的后续工作，先呈现验证结果，不靠模拟成功掩盖充电内容的实际限制。

## 6. 测试方案

1. **纯单元测试**：时间范围与跨类最新 N、置顶排序、目录清理与判重、断点状态转移、字幕/ASR 合并、Mermaid 转义和敏感信息遮盖。
2. **离线集成测试**：固定的脱敏响应样本模拟分页、转发动态、多图/长文、多 P、无字幕、充电不可见、限流与异常；替身 LLM 检查分块不漏尾段，替身下载器检查失败重试。
3. **本机功能测试**：在 Windows 验证 FFmpeg、ASR 模型、Mermaid CLI；检查媒体可播放、PNG 非空且中文/图片未被裁掉。长动态、多图均做目视检查。
4. **授权在线验收**：仅使用用户提供的有权账号与样本，手动执行一次首次采集和一次增量重跑；核对三类内容与本地目录、状态摘要，确认未访问无权内容。在线测试默认不在 CI 运行、不保存凭据。

## 7. 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| B 站列表或详情接口变化，充电条目仅部分可见 | 阶段 0 做样本矩阵；适配层隔离接口；区分未发现、无权、失败，不承诺无法验证的全量 |
| 限流或登录态过期 | 限制请求频率和并发、对暂时失败退避；遇到明确风控即停止并提示人工处理，不绕过验证 |
| 视频格式与字幕获取差异 | 以实际授权样本验证下载器和 FFmpeg，保留各 P 的原格式及来源标记 |
| Windows 本地模型资源消耗/首次安装复杂 | ASR 可选安装、可调模型；安装检查给出明确错误 |
| 长动态 PNG 尺寸、LLM 长上下文或导图语法出错 | 分段排版但交付单张图；LLM 分块与确定性导图序列化；各步骤独立可重试 |
| 第三方 LLM 处理充电文字、Cookie 泄露 | 用户显式配置 LLM；只发送文字稿，不发送 Cookie 或原视频；凭据不入库、不入日志 |
