# B 站 UP 主内容归档与视频整理工具需求文档（草案）

状态：需求已确认  
日期：2026-09-23

## 1. 目标与范围

输入一个 B 站 UP 主 UID，获取该 UP 主可由当前登录用户访问的动态、视频和专栏，按条目归档到本地。下载动态配图与视频；提取视频文字，生成逐视频总结和思维导图；为每条动态生成可阅读的图片。

工具供个人本地使用，不提供公开分享、付费内容破解或登录权限绕过能力。充电内容仅在用户提供的 Cookie 对应账号本身具有访问权限、且平台实际提供该内容时处理；无权限、失效或不可获取的条目要记录原因，不伪装成成功。

## 2. 输入与运行方式

| 项目 | 要求 |
| --- | --- |
| UID | 必填，指定目标 UP 主；启动时校验格式并读取 UP 名称、头像。 |
| Cookie | 用户通过环境变量或本地配置文件提供；配置文件不得提交到代码仓库，Cookie 不写入输出文件或日志；启动时检查登录态，过期时明确提示。 |
| 输出目录 | 可配置，默认在当前工作目录下；不同 UID 的内容分开存放。 |
| 内容范围 | 动态、视频、专栏均可单独开启或关闭；支持首次采集与后续增量运行。 |
| 筛选 | 支持按发布日期起止时间筛选，或在动态、视频、专栏三类内容中按发布时间合计获取最新 N 条；两种条件同时提供时，先按日期筛选，再从结果中合计取最新 N 条。 |
| 文字提取 | 可设置是否在无可用字幕时执行本地语音转写；可关闭，不调用云端识别服务。**不提供本地视频画面 OCR**（见第 7 节）。 |
| 总结配置 | 使用 OpenAI 兼容接口；用户配置接口地址、模型、凭据及自定义 prompt。允许把视频文字（包括充电内容）发送给用户选定的模型服务；密钥仅从本地安全配置或环境变量读取。 |
| 并发配置 | 视频下载并发数可配置，限制并发请求，支持失败重试。 |
| 运行环境 | Windows，Python 命令行脚本；用户手动运行，暂不提供定时同步。 |

具体命令行参数、配置文件格式及默认值在技术设计时确定。

## 3. 功能需求

### 3.1 发现与归档

1. 按 UID 列举动态、视频、专栏，分页获取直到到达指定范围；跨三类内容按发布时间排序后合计取最新 N 条（如指定），同一时刻的条目按类型与平台 ID 稳定排序。保存原始链接、平台 ID、发布时间、标题/正文、类型、作者信息及访问状态。
2. 一条内容对应一个文件夹；文件夹名包含北京时间发布日期、内容类型、可识别的标题/摘要及唯一 ID，例如 `2026-09-23_视频_标题_BVxxxx`。不合法路径字符应清理，重名不覆盖。
3. 重复运行时按平台 ID 判重；已成功的步骤跳过，未完成的步骤可重试。应保留处理状态，避免重复下载和重复调用 LLM。
4. 被删除、仅 App 可见、权限不足、接口变更或暂时失败时，记录条目和失败原因（若能发现该条目），其他条目继续处理。
5. 仅处理 Cookie 对应账号可见的内容；区分“该账号无权查看”“未发现条目”和“抓取失败”，不得绕过充电档位、地区或其他访问控制。

### 3.2 动态

1. 保存动态原文、发布时间、原链接、配图原文件；保留原图顺序及必要的图文对应关系。
2. 每条动态生成一张 PNG 图片，至少包含 UP 名称、头像、发布时间、动态正文和动态配图。长文本/多图应自动排版成单张高度随内容增长的长图，不截断主要内容、不分页。
3. 对可见的转发动态、视频卡片、投票、表情等复杂类型，尽量保留可获取的文本、图片、链接和类型说明；无法完整渲染的部分在元数据中标记。只归档可见内容，不额外采集评论区。

### 3.3 视频

1. 下载当前账号有权获取的视频文件，保留标题、简介、发布时间、BV 号、原链接、分 P 信息。多 P 视频作为一个条目、一个文件夹归档，各 P 媒体文件保存在同一文件夹内，不强制拼接为单个视频文件。下载使用可配置的多线程/并发机制，支持断点续传或可恢复的重试，完成后校验文件可播放且大小非零。
2. 提取视频文字，保存带时间戳的文字稿与便于阅读的纯文本。优先使用可获取的字幕；用户开启语音转写时，对无可用字幕的部分执行本地 ASR。各 P 的文字稿保留分段和时间戳，并生成一个合并的整视频文字稿，标注字幕、ASR 各自来源；不得将标题/简介冒充完整文字稿。
3. 每个视频基于完整可用的文字稿生成总结，保留使用的模型、prompt 版本、生成时间和失败状态；长稿应分段处理再合并，不直接丢弃尾段。
4. 每个视频基于合并文字稿/总结生成一份思维导图，保存 Mermaid mindmap 源文件 `mindmap.mmd`，并渲染 `mindmap.png`。总结失败不影响原视频和文字稿保存。
5. 合集中的每个 BV 号按独立视频处理；不纳入互动视频和直播回放。
6. 无字幕且未开启 ASR 时，不生成虚构的完整文字稿；若可用文字不足以支撑可靠总结，应将总结和思维导图标为“缺少文字来源”，供用户开启 ASR 后重试。

### 3.4 专栏

1. 保存标题、作者、发布时间、原链接、正文及正文中可获取的图片，保留基本段落、标题、列表与图片顺序。
2. 以 Markdown 为主要可阅读格式，同时保存元数据；付费/充电专栏遵循与其他内容相同的权限规则。

## 4. 建议输出结构

```text
output/
  <UID>_<UP名称>/
    index.json
    2026-09-23_动态_摘要_<动态ID>/
      metadata.json
      content.md
      images/
      render.png
    2026-09-23_视频_标题_<BV号>/
      metadata.json
      videos/
        P01.mp4
        P02.mp4
      transcript.txt
      transcript_timed.srt
      summary.md
      mindmap.mmd
      mindmap.png
    2026-09-23_专栏_标题_<专栏ID>/
      metadata.json
      article.md
      images/
```

`index.json` 用于记录条目清单、步骤状态及错误，不含 Cookie 或 API 密钥。具体媒体扩展名随实际格式调整；单 P 视频仅保存一个视频文件。

思维导图交付格式已确定为可编辑的 Mermaid `.mmd` 源文件和便于查看的 PNG 图片。

## 5. 非功能与边界

- 仅抓取用户账号在运行时可合法访问的内容；遵守平台服务条款和合理请求频率，遇到风控/限流时停止或退避，不做验证码绕过、权限破解或批量账号轮换。
- Cookie、LLM 密钥和含充电内容的本地归档均视为敏感数据；日志不打印密钥和 Cookie，输出默认仅保存在本机，传入第三方 LLM 前需让用户知悉。
- 单条失败不应中断整批任务。运行结束提供成功、跳过、权限不足、失败的数量与可定位的错误信息。
- 下载与总结步骤解耦：LLM 服务暂时不可用时，已获取的文件保留，后续可单独重试生成。
- 平台页面和可用接口可能变化；某些内容可能仅在特定客户端展示，实际可发现性需在实现阶段验证，不能承诺“指定 UID 下所有充电内容必然完整列出”。

## 6. 验收标准

1. 给定有效 UID、可用 Cookie 和指定日期范围，能将三类可访问内容分别保存到独立、含日期和类型的文件夹，重复运行不产生重复条目。
2. 含多张图片的动态保存全部可获取原图，并生成包含 UP 名称、头像、日期、正文和图片的完整 PNG。
3. 有字幕的视频产生带时间戳文字稿、总结、思维导图源文件及 PNG；无字幕视频按语音转写开关处理；失败时有明确状态。
4. 可配置视频下载并发数；部分任务失败后重跑只补足未完成步骤。
5. Cookie 无效、充电权限不足或 LLM 调用失败时，报告具体原因，不泄露凭据，也不覆盖已完成结果。
6. 日期范围与最新 N 条模式均可运行；最新 N 条从三类内容中按发布时间合计选取。多 P 视频归档在同一个文件夹中，生成一份合并总结及思维导图。
7. 本地 ASR 可开启、关闭；关闭时不运行识别，也不将媒体文件发送给云端识别服务。

## 7. 已确认边界

- 不纳入互动视频和直播回放；合集中的普通视频仍按 BV 号处理。
- 暂不提供定时任务，用户手动运行；重复运行时支持增量补齐。
- 动态只生成单张 PNG，允许图片高度随内容增长，不分页。
- Cookie 支持环境变量或本地配置文件，具体参数名与配置格式由实现确定。
- **不提供本地视频画面 OCR**（2026-09-23 决定）。视频文字来源只有两种：平台现成字幕、本地 ASR 语音转写。因此不产生 `ocr.txt`，也不引入 OCR 依赖链。理由见 [阶段 0 组件验证记录](docs/stage0-component-verification.md) 第 2.1 节。
